# QA-072 控制台满容量入队成本

## 基线与修改

2026-11-23 开始前及恢复工作时均成功 fetch。工作基线 `35f9a7ce46ce301669f125ad6c1a44533b9fa9b5` 与交付分支一致，包含远端 master `42df3f730be8ddd157a6aaca8d9a2b908638c950`（0.1.44）。

持续性能审阅发现，控制台使用深层响应式数组保存最近5000条记录。满容量后，每条输出执行头部 `splice`，移动其余所有响应式元素；控制台隐藏时也支付这部分成本。本项登记为性能改进，旧实现输出契约正确，不将性能计时描述成旧版功能测试失败。

改为5000槽的普通环形数组，入队覆盖最旧记录并递增响应式版本；消费时按时间顺序生成快照。保留记录数、ID、时间、输出类型及原始多行文本。清空同时释放环形存储和已缓存的快照。现有消费者只读历史，控制台视图继续使用既有选区映射和帧调度，本项没有修改视图产品代码。

这是有界内存换取较低入队成本的实现：控制台隐藏后，computed可能保留上一次最多5000条的快照，连同环形数组最多约10000个条目对象（不含外部持有引用）。因此不能声称所有时刻内存中严格只有5000个对象。清空会主动求值为空快照，释放旧缓存。可见面板遇到分散在多个任务中的输出时，仍可能多次物化5000项快照；同步输出的合并不能推导为原生每帧只求值一次。

## 独立入队基准

可复现脚本为 `apps/desktop/src/stores/consoleStore.benchmark.test.ts`，使用实际Pinia/Vue store、Node/happy-dom。每轮预填5000条，再计时输入300条；隐藏模式结束才读历史，批读取模式每30条读取一次首尾。两模式各3轮，全部检查最终5000条、首项line 300和尾项line 5299。前后单独执行，当时无其他测试或构建；不设置依赖机器速度的通过阈值。
