# Git 术语表

| 术语 | 在 gitx 中的含义 |
| --- | --- |
| Repository / 仓库 | 包含 Git 历史与引用的项目；工作区可包含多个仓库 |
| Workspace / 工作区 | 当前打开的文件夹，File 的浏览范围 |
| Working tree / 工作树 | 磁盘上正在编辑的文件 |
| Index / Staging area / 暂存区 | 下一次普通 Git 提交准备使用的内容 |
| Commit / 提交 | 一次保存到 Git 历史的快照，包含说明与作者等信息 |
| HEAD | 当前检出的提交或分支位置 |
| Branch / 分支 | 指向一条开发线当前提交的可移动引用 |
| Upstream / 跟踪分支 | 当前本地分支默认同步的远程跟踪分支；也常被用作父仓库 remote 名，两种含义看上下文 |
| Remote / 远程 | 一个名称与服务器仓库地址的配置，如 origin |
| Fetch | 下载提交和引用，不自动把它们合入当前分支 |
| Pull | 获取并整合远程变化 |
| Push | 将本地提交发送到远程并更新引用 |
| Diff | 两个版本之间的差异 |
| Hunk / 修改块 | 一段连续的差异，用于理解或拆分修改 |
| Changelist / 更改列表 | gitx 中按任务组织本地变更的分组，不是 Git 分支 |
| Stash | Git 管理的临时修改保存记录 |
| Shelf / Shelve / Unshelve | gitx 的保存记录，以及保存/应用该记录的操作 |
| Patch / 补丁 | 记录文件变更的文本/二进制补丁文件，可导入 Shelf |
| Merge / 合并 | 将另一条历史整合进当前分支 |
| Rebase / 变基 | 将提交重放到另一基点，通常产生新 SHA |
| Cherry-pick | 将选中提交的变更应用到当前分支 |
| Conflict / 冲突 | Git 不能自动决定如何组合的内容，需要选择或编辑结果 |
| Amend | 替换最近一次提交，改变其内容或说明 |
| Revert | 创建反向提交，保留原历史 |
| Reset | 移动分支位置，按模式处理暂存区和工作树 |
| Detached HEAD | 直接检出一个提交而未位于本地分支上，继续开发前可新建分支 |
| Tag / 标签 | 给某个提交命名，常用于版本；不等同于已发布安装包 |
| Worktree | 同一仓库额外的独立工作目录 |
| Submodule / 子模块 | 父仓库中引用的独立 Git 仓库及其特定提交 |
| Hook | Git 操作前后运行的项目脚本，可能使提交被拒绝 |
| Force with lease | 在预期远程状态条件下替换历史的强推方式，仍需协调共享历史 |

实操从[第一次提交](./getting-started)开始；恢复问题看[常见问题](./troubleshooting)。
