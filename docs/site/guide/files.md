# 文件管理与编辑

File 工具窗显示工作区中的文件，未修改的文件也在这里。普通非 Git 文件夹同样可用。

## 浏览与编辑

1. 点击左侧 **File** 或按 `Alt+1`。
2. 点击箭头展开目录。目录按需加载；尚未展开的子目录不会全部提前扫描。
3. 单击选中文件，双击或 Enter 打开文本编辑器。输入后按 `Ctrl+S` 保存，标签中的未保存状态随之消失。
4. 通过编辑器右键菜单使用 Undo、Redo、Cut、Copy、Paste、Select All 和 Save。
5. 顶栏除新建/刷新外，可用**定位当前文件**（准星）把活动编辑器或 Diff 对应路径滚到可见并选中。

![File 树与文件编辑器](/screenshots/files-en.jpg)

树上的 Git 标记表示文件变更，父目录上的标记汇总子级状态。设置中启用紧凑目录后，已加载的单子目录链会合并显示，例如 `src/components/ui`。

## 新建、改名、复制、移动和删除

| 操作 | 步骤 |
| --- | --- |
| 新建文件/目录 | 选择目标目录，使用顶部按钮或右键 **新建文件 / 新建文件夹**，输入名称并确认 |
| 重命名 | 选中一个项目，按 F2 或右键重命名，输入新名称；已打开编辑器会跟随路径更新 |
| 复制到 | 多选后右键 **复制到**，填写目标目录并确认；源文件保留 |
| 移动到 | 右键 **移动到**，填写目标目录，检查列表后确认 |
| 删除 | 选中后按 Delete、点顶栏垃圾桶，或右键 **删除…**；确认后移入系统回收站。若相关标签有未保存草稿，会再确认是否放弃草稿 |

目标已存在时不会静默覆盖。批量操作可能部分成功，按结果逐项检查。回收站操作失败会保留源文件，不自动改为永久删除。恢复文件可到 Windows 回收站操作，回到 gitx 刷新。

删除失败的文件会保留编辑器草稿和未保存标记，仍可继续保存或重试删除。仅当文件成功移入回收站，且草稿仍是确认时的内容，才关闭该标签；确认或回收期间产生的新编辑会保留，并提示文件已在磁盘上删除。

确认后开始执行时，File 面板显示正在进行的操作，左下角任务队列同时显示操作名称和工作区路径，直到文件树刷新完成。等待确认时不会提前显示运行任务；保存普通非 Git 文件也会显示保存任务。

目录不能移动到自身或子目录；仓库根、冲突文件、工作区之外的目标，以及某些链接/跨卷移动受到限制。遇到错误先看具体路径和原因，不要把部分成功的操作全部重复一次。

## 多选和拖放

用 Ctrl 点击切换单项，Shift 扩展范围。将选择拖到目标目录通常是移动；按住 Ctrl 或 Alt 拖动表示复制。拖到空白根区域作用于工作区根目录，放下后核对确认框。

将文件拖到左侧 Commit 入口并停留可切换面板，再放到某个 Changelist，把适用的变更分配过去。此功能依赖变更归属，不会因为拖动普通未修改文件就创建 Git 提交。

## 右键辅助操作

- **Copy Path / Copy Relative Path**：复制绝对路径或工作区相对路径，多选可批量复制。
- **Reveal**：在系统文件管理器显示文件或目录。
- **Open in Terminal**：在目标目录开始终端操作。
- **Show Diff / History**：用于活动 Git 仓库中的适用文件；其他仓库或非 Git 文件通常只按普通文本打开。

File 树中 **F4 是 Diff**；想编辑文件用 Enter/双击。更多快捷键见[速查表](./shortcuts)。

## 显示隐藏和忽略文件

到 **Settings → Project Files** 分别开启显示隐藏、显示忽略文件或紧凑目录。这些设置与 Commit 面板的“显示忽略文件”独立。`.git` 元数据目录不作为普通可操作工作文件。

树顶部 **Filter loaded files** 只过滤已加载的节点；要搜索整个工作区，使用 `Ctrl+P` 或 `Ctrl+Shift+R`。工具栏上的定位图标可将当前编辑器/Diff 文件滚动并选中到树中。见[搜索说明](./search)。

## 编辑范围

普通文本编辑、文件内替换和保存会保留未改动位置的 LF、CRLF 或 CR 换行，包括混合换行及 UTF-8 BOM；新增换行沿用文件中第一个换行的类型，没有换行的文件使用 LF。撤销会恢复被删除的原始换行，保存后继续编辑也沿用相同规则。

File 树、搜索结果和 Commit 的「打开文件」使用同一套文本读取规则：完整读取磁盘上的 UTF-8 正文，不再以 5 MiB 为上限。二进制、无效 UTF-8 或读取失败会显示只读提示，不能保存为文本。大文件编辑需要容纳整个文档的内存，并会省略额外的 HEAD 行变更计算；普通文件即使无法读取 HEAD 差异，也仍能打开有效正文。保存前先处理未解决冲突。文件内查找能搜索草稿，全局搜索读取磁盘；操作见[搜索与替换](./search)。
