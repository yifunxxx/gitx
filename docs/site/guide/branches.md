# 分支与标签

## 找到分支并切换

点击顶部当前分支，或在 Log 左侧使用 Branches。可按名称搜索；带 `/` 的分支按目录分组，星标用于收藏，最近分支便于返回。Settings 中可控制目录分组、最近分支和标签显示。

单击分支用于选择/查看，**双击或右键 Checkout 才执行切换**。切换后检查顶部当前分支和 Log 的 HEAD 标识。遇到本地修改会被覆盖的提示，先保存、提交或 Stash/Shelf；不要为了切分支直接丢弃需要的内容。

## 新建、改名和删除

| 任务 | 操作 | 完成后检查 |
| --- | --- | --- |
| 新建分支 | 在目标分支/提交菜单选择 New Branch，填写名称和起点，按需要勾选 Checkout | 分支出现；只有选择检出时当前分支才改变 |
| 从远程分支检出 | 选择完整远程分支，如 `origin/feature/search`，Checkout | 建立或使用对应本地分支，核对 upstream |
| 改名 | 对本地分支选择 Rename，填写新名并确认 | 本地名称更新；远端旧名称不会自动按你的想象同步改名 |
| 删除本地分支 | 选中非当前本地分支，Delete 并确认 | 检查被删名称及未合并提示 |
| 删除远程分支 | 对远程分支执行 Delete 并确认 | 这会修改远端，影响协作者；确认远程和完整路径 |

**Copy Branch Name** 可复制完整名称。不要因列表只显示目录末段就忽略上层路径。

## 分支上下文操作

- **Merge into Current**：把选中分支合入当前分支。
- **Rebase Current onto Selected**：把当前分支变基到选中分支。
- **Checkout and Rebase**：先检出目标，再按菜单所示方向变基；执行前核对源和目标。
- **Push / Pull with Merge / Pull with Rebase**：对菜单目标进行同步；仍要检查弹窗中的分支和 remote。
- **Compare with Current**：查看双方独有的提交，点击 **Swap** 交换方向。以每栏“在某分支中、不在另一分支中”的标题为准。

比较没有把代码合并，也没有切换分支。详情见[同步](./sync)和[合并](./conflicts)。

## 创建与使用标签

1. 在 Log 选中要标记的提交，右键 **New Tag / Create Tag**。
2. 输入名称，例如 `v1.2.0`，核对目标提交。
3. 填写说明可创建带说明的标签；需要覆盖同名标签时必须明确启用 Force。
4. 如勾选创建后推送，先核对显示的远程；当前入口使用可用列表中的第一个 remote。
5. 完成后在 Tags 区域检查。推送失败可能已成功创建本地标签，窗口会说明并允许仅重试推送。

不要通过重新创建标签来处理纯网络失败。标签只是 Git 引用，创建标签本身不代表软件安装包或 GitHub Release 已发布。

检出标签通常进入 **detached HEAD**。若要继续开发，先从该提交新建本地分支。删除标签前确认是本地标签还是远端引用。
