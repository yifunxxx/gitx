# 常见问题与恢复

## 软件找不到 Git / 提交提示身份未知

在 Settings → Git 选择 `git.exe`，Test 后保存。提交提示作者信息缺失时，在当前仓库终端设置 `git config user.name` 和 `git config user.email`，详见[入门](./getting-started)。安装 gitx 不等于已经配置好 Git 身份与远程权限。

## 找不到功能或按钮灰色

先按 `Ctrl+Shift+A` 搜索命令，再检查上下文：是否打开 Git 仓库、是否选中文件或提交、是否有写任务正在运行、是否处于冲突/变基状态。不同功能需要不同数量的选择；例如比较两条提交需要两条，Squash 至少两条。

File/Commit 的快捷键语义不同，F4 在 Changes 打开编辑器，在 File 打开适用 Diff。当前没有 UI 的后端能力不会因为搜索名称自动出现，见[功能索引](./features)。

## 列表为空、文件丢失或搜索没有结果

先清除过滤、检查活动仓库并刷新。File 顶部只过滤已加载节点，全局查找用 `Ctrl+P`。查看隐藏/忽略规则、搜索截断提示，以及文件是否超过文本读取范围。确认磁盘路径后再判断文件是否真的被删除。

Log 空白时先 Clear 筛选，核对分支/路径范围、加载状态和 Git 错误。无首提交的新仓库没有历史是正常情况。

## 无法编辑、保存失败或内容未进提交

Diff/历史是只读视图；从 File 打开当前文件。保存失败先处理权限、文件锁、路径变化、冲突或 UTF-8/大小限制，保留编辑器草稿。保存后还需 Stage/勾选并 Commit；提交后还需 Push。不要把标签关闭或保存按钮按下等同于全部步骤成功。

## 更新、合并或变基停住

查看后台任务和仓库状态横幅。若等待用户处理冲突，先 Resolve Conflicts、Save and mark resolved，再 Continue。若计划暂停在 edit，完成编辑/提交后继续。Skip 会丢掉当前待重放提交；Abort 会中止当前操作。

Smart 操作的本地修改恢复可能晚于合并本身。看到恢复失败时保留 Stash/Shelf，核对工作树；不要删除系统保护记录。

## 推送失败、认证反复弹出

检查 remote URL、端口、账号权限和 HTTPS 令牌/SSH 环境；读 Console 中的具体错误。凭据“记住”失败提示意味着存储可能未成功。远端领先使用 Fetch + Pull/Update，认证失败不能靠强推修复。提交若已经成功，只需重试推送。

## 执行后报错，是否应该再点一次

先区分阶段：创建标签后推送失败、本地提交后刷新失败、文件批量操作部分成功，都可能已经产生结果。检查 Log、Tags、磁盘文件、任务输出及对话框的阶段说明，再重试未完成阶段。

## 怎样恢复误操作

| 情况 | 优先检查 |
| --- | --- |
| File 删除 | Windows 回收站；恢复后刷新 |
| Shelf 删除 | Show deleted → Restore，再按需 Unshelve |
| Stash 已应用 | Apply 保留记录；Pop/Drop/Clear 的行为不同，先查看实际列表 |
| 最近支持的历史重写 | Undo Last History Rewrite 是否可用、备份分支、Git reflog |
| 历史文件覆盖本地 | 之前保存的提交、Stash/Shelf 或其他备份 |
| 已共享提交需要撤销 | 优先 Revert，保留协作历史 |

回收站、Shelf 最近删除和 Git reflog 处理的对象不同，不能互相替代。未提交、未保存、未备份的数据不保证可恢复。

## 更新下载完了，版本为什么没变

下载完成只表示安装文件准备好。保存工作，按更新中心的重启更新流程完成安装，再启动并检查 About 的当前版本。检查/下载失败时可打开 Releases，不能把失败当作“已经最新”。

## 提交问题报告

提供软件版本、系统、具体入口、最短复现步骤、预期与实际行为，以及经过检查的截图/日志。说明“自动测试通过”“原生操作已验证”“安装版已更新”中的哪一步实际完成。项目反馈入口：[GitHub Issues](https://github.com/yifunxxx/gitx/issues)。
