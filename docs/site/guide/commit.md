# 提交与更改列表

## 先分清选择、勾选和暂存

单击文件行是“选中”，用于 Diff、右键菜单等操作；复选框是“勾选”，决定 Changelist 模式下提交的范围；Stage 则把内容写入 Git 暂存区。三者不能混为一谈。

| 模式 | 在哪里设置 | 提交内容如何确定 |
| --- | --- | --- |
| Changelist（默认） | Settings → Git，关闭 staging mode | 勾选本次要提交的文件，更改列表用于按任务分组 |
| Staging | Settings → Git，开启 staging mode | 先暂存文件或选定的修改行；提交当前暂存区内容 |

同一文件的不同修改可以分到不同 Changelist；也可使用[部分暂存](./diff)，在暂存区模式下检查 Staged 内容。

## 一次普通提交

1. 按 `Alt+0` 或 `Ctrl+K` 打开 Commit。
2. 展开目录查看文件。工具栏可以切换树形/平铺列表；`M` 为修改、`A` 为新增、`D` 为删除、`?` 为未跟踪，重命名会带来源信息。
3. 双击文件查看 Diff。未跟踪文件需纳入版本控制或在提交范围中勾选。
4. Changelist 模式勾选目标文件；Staging 模式在右键菜单选择 **Stage**，检查 Staged 分区。**Unstage** 仅撤销暂存，保留磁盘修改。
5. 输入提交说明。第一行概括目的，必要时空一行补充正文。检查 **Run Git hooks**，点击 Commit。
6. 等待结果，在 Log 核对提交和文件。发生错误时先查看消息及 Console，保留草稿，解决原因后重试。

![Commit 与双栏 Diff](/screenshots/commit-diff-zh.png)

**Commit and Push** 是提交与打开 Push 的连贯入口；推送仍需核对目标。提交成功后的刷新提示不等于提交失败，重试前先查看 Log，避免重复提交。

## 使用 Changelist 拆分任务

1. 点击 **New Changelist**，输入 `Search improvements` 等名称。
2. 在 Changes 中选择文件，右键 **Move to Changelist**，选择目标列表；也可拖放到对应列表。
3. 在列表菜单中设为活动列表、改名或删除。活动列表用于归属新变更；删除列表不等于删除磁盘文件。
4. 提交时只勾选当前任务文件。列表名称不会自动变成 Git 分支，也不会自动推送。

开启 Settings → Git → **Allow per-hunk changelists** 后，从 Changelist 打开文件 Diff，比较方向为 **HEAD → Local**。点击修改块旁的列表名称，选择目标列表。同一文件可以出现在多个列表中，并显示“部分”；文件、目录和列表的复选框只选择该列表拥有的块，多选 **Commit Files** 窗口使用相同范围。

新增的独立修改块进入活动列表，能唯一对应的旧块保留归属。外部编辑导致内容合并、拆分或无法唯一对应时，会显示“需复核”，请刷新并检查整个文件，再重新分配块。勾选时保存预览；内容或归属发生变化后旧提交会拒绝，请取消勾选后重新检查并勾选，或关闭并重新打开多选提交窗口。

整文件 **Move to Changelist** 或拖放会覆盖这个文件所有块的归属；删除列表只迁移它拥有的块。关闭按块设置会禁用分配按钮，但保留已有归属和提交范围。存在部分归属时需要明确勾选文件，不能通过空选择隐式提交暂存区。

按块提交会保留未选工作内容和可合并的未选暂存内容；与未选暂存发生重叠时先拒绝提交。新文本文件和删除文件支持按块归属，空文件或仅模式变化使用整文件。二进制、大文件、符号链接、特殊过滤器/编码、重命名比较及 WSL Git 不支持按块分配；混合部分提交中的非普通文件请单独整文件提交。

## 只提交选中文件

文件右键 **Commit Files** 打开独立窗口，核对文件清单并输入说明后提交。该窗口拥有自己的提交说明与选择；面板原来的草稿不会因此被替换。不要把鼠标高亮误认为全部文件已经勾选。

## Amend 最近一次提交

勾选 **Amend**，等待载入当前 HEAD 的完整说明，修改说明或加入需要的文件，然后提交。取消 Amend 会回到普通草稿。Amend 会生成新的提交标识；已经推送的提交需要与协作者协调，后续推送可能要求 force-with-lease。见[历史整理](./rewrite)。

## 回退、忽略与停止跟踪

| 命令 | 使用方式 | 结果 |
| --- | --- | --- |
| Rollback | 选中更改，打开回退窗口，核对文件/选项并确认 | 丢弃所选本地修改；执行前保存需要的内容到 Stash/Shelf |
| Ignore | 对未跟踪路径使用 Ignore | 写入 `.gitignore` 规则；该文件可提交给团队 |
| Stop Tracking | 对已跟踪文件打开停止跟踪窗口 | 从索引移除，磁盘文件保留；可选择同时加入 `.gitignore`，之后提交这一索引变更 |
| Open .git/info/exclude | 从 Find Action 打开 | 使用 Git 的本地排除文件，规则不随普通提交共享 |

已有跟踪文件不会因为加入 `.gitignore` 自动停止跟踪。File 中“删除”移入回收站与 Changes 中“回退”是不同动作。

## 键盘操作

Changes 树支持方向键、Home/End、PageUp/PageDown；左右键展开/折叠。Shift 连选，Ctrl 保持独立导航，空格勾选，Shift+F10 打开菜单。Changes 的 **F4 打开文件编辑器**；File 树的 F4 打开适用的 Diff，取决于焦点所在区域。
