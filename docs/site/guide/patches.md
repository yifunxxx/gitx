# 补丁导入与导出

补丁用于传递文件变更，不要求对方拥有你本机的 Shelf 数据。补丁可包含源代码和其他文件内容，分享前先阅读。

## 从当前修改创建补丁

1. 打开仓库，在 Changes 选择要导出的文件；如果没有行选择，命令会使用已勾选文件；都没有时按默认范围处理。
2. 通过 VCS 菜单或 Find Action 执行 **Create Patch**。
3. 等待成功提示，记录提示中的输出路径及字节数；默认在 Git 元数据目录的 `gitx/changes.patch`，再次导出会使用同一路径，需保留旧补丁时先复制出来。
4. 打开生成的 `.patch` 检查范围。这个入口可能直接生成到默认路径，并不等同于 Shelf 的“另存为”窗口。

该入口比较 HEAD 与本地内容，支持二进制补丁；**未跟踪文件不会自动包含**，需要先 Add/Stage 后再导出。没有首提交的仓库没有 HEAD，此时先建立初始提交。创建补丁不代表已提交或已推送，也不会自动发送给其他人；重要内容另做备份。

## 导出已有 Shelf

1. 到 Stashes & Shelves 选中一个有效 Shelf。
2. 点击 **Preview** 核对保存内容。
3. 点击 **Export Patch**，在系统保存窗口选择路径和 `.patch` / `.diff` 文件名。
4. 等待完成后核对文件。取消保存窗口不会导出。

导出的内容来自选中的保存记录；后续对工作区的编辑不会自动加入该补丁。

## 导入补丁到 Shelf

1. 打开接收变更的仓库。
2. 点击 **Import Patch**，选择 `.patch` 或 `.diff`。
3. 导入成功后在 Shelf 中检查新记录，展开文件并 Preview。
4. 确认适用于当前仓库，再 Unshelve；随后在 Changes 中审查、测试并提交。

**导入只建立 Shelf 记录，不立即改动工作文件。** 这给你留出先检查再应用的机会。补丁中包含的路径或内容不适用时，应保持工作区现状并阅读错误信息。

## 应用失败时

常见原因包括基线版本不同、相同位置已有本地修改、文件路径变化或不支持的补丁内容。先保存本地工作，再考虑切换到匹配的基线。部分成功时逐项检查 Changes 与 Shelf 记录，不要因失败提示把整个补丁连续应用多次。

需要按任务分批应用时，导出前将任务拆为多个 Shelf；当前 Shelf 界面没有逐文件 Unshelve 勾选入口。见[Stash 与 Shelf](./stash-shelf)。
