# 整理与撤销历史

历史重写会改变提交 ID，通常适用于尚未共享的本地工作。操作前在 Log 确认范围，必要时从原 HEAD 新建备份分支；已经共享的提交优先考虑 Revert。

## 根据目标选命令

| 目标 | 命令 | 结果 |
| --- | --- | --- |
| 修改最近一次提交 | Commit → Amend | 替换 HEAD，可补充内容或说明 |
| 修改某条历史说明 | Log → Edit Commit Message / F2 | 重写该提交及受影响的后续历史 |
| 合并多次提交 | Squash Commits | 选择至少两个提交，编辑合并说明，生成整理后的历史 |
| 把本地修补放进旧提交 | Fixup / Squash Into | 将本地更改折入目标；Squash Into 可编辑组合说明 |
| 移除指定提交 | Drop Commits | 从重写后的历史移除选择的提交 |
| 撤销最新提交但保留修改 | Undo Commit | 对 HEAD 做 soft reset，修改保留在暂存区 |
| 撤销已发布变更 | Revert Commit | 新建反向提交，保留原历史 |
| 移动当前分支到某处 | Reset Current Branch to Here | 按 Reset 模式处理索引与工作区 |

## 修改说明、Squash 与 Drop

1. 在 Log 选中目标；多提交操作使用 Ctrl/Shift 选择。
2. 右键选命令，核对 SHA、提交说明及数量。
3. 编辑说明时保留需要的正文；Squash 写出能代表合并后整体目的的说明。
4. 确认后等待任务结束，检查新 Log。若中途出现冲突，按[冲突处理](./conflicts)继续。

后端会校验操作范围；不能把任意跨分支、不连续或合并历史的选择都当成可直接整理的序列。

## 交互式 Rebase

在 Log 选择起点并打开 **Interactively Rebase from Here**，等待计划加载。以窗口生成的提交范围、顺序和预览为准，不要仅按 Log 由新到旧的视觉顺序判断执行顺序。

| 动作 | 含义 |
| --- | --- |
| pick | 保留并重放提交 |
| reword | 重放并修改说明 |
| edit | 在该提交处暂停，供修改后继续 |
| squash | 合入前一个提交并整理说明 |
| fixup | 合入前一个提交，丢弃此条说明 |
| drop | 不重放此提交 |

设置每行的动作，必要时 **Reset actions** 恢复计划动作，然后 **Start Rebasing**。生成计划包含合并控制行时，尊重界面说明，不把它们当普通可任意移动的提交。暂停后使用 Continue/Skip/Abort；Skip 会省略当前提交。

## 提取或丢弃某个提交的部分文件

选中一个提交，打开 **Extract Selected Changes** 或 **Drop Selected Changes**。在文件选择窗口搜索、勾选路径；提取时填写新提交说明，核对后提交。这里的选择粒度是**文件**，不是从 Diff 中随意圈出的几行；按行暂存本地修改见[Diff](./diff)。

## Reset 模式

选择一个目标提交，打开 Reset，检查影响提交数量与本地修改提示。

| 模式 | 分支/索引/文件的变化 |
| --- | --- |
| Soft | 移动 HEAD，保留索引和工作区，修改仍可提交 |
| Mixed（默认） | 移动 HEAD 并重置索引，保留工作区修改但不再暂存 |
| Hard | 移动 HEAD、索引和工作区，丢弃相应本地内容；需要再次确认 |
| Keep | 尝试移动 HEAD 并保留本地修改；有覆盖冲突时拒绝 |

先保存需要的内容再执行 Hard。Reset 与 File 回收站删除没有相同的恢复语义。

## Revert 与恢复

Revert 会产生抵消原变更的新提交，适合共享历史。发生冲突时检查状态横幅，完成解决后按可用入口继续；取消时用 **Abort Revert**。

**Undo Last History Rewrite** 在存在可撤销记录时可用，用于回到最近一次受支持重写之前。它不是任意文件删除或所有外部 Git 操作的通用撤销。恢复前保留当前需要的修改；若按钮不可用，先检查备份分支、Git reflog 或保存记录，不重复运行不确定的重写。
