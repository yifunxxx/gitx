# QA040：自动化客户端生命周期与静置CPU对照

日期：2026-11-27。开始前读取台账、fetch并检查master和交付分支；干净基线 `50c33dc0bd8169558a33eb2efa4b3da05debbfb0` 包含master `50a4802dd23f61055668e165f6fe7c0b93b17680`，版本0.1.56。全程主线程。

## 结论与关闭范围

同一个GitX进程中，通过受支持的JavaScript会话重置使自动化客户端退出后，UIA连接集合变为空，静置CPU从约0.38核降至接近零；重新连接后恢复高CPU，再次断开后归零。2000修改文件、三个只读差异标签和可见Log的场景也取得高→低→高对照。期间没有重启GitX、禁用可访问性、修改产品事件循环或强杀工具进程。

这些对照将**本测试环境的静置高CPU**归因到自动化客户端生命周期带来的开销，闭合QA040最初“停止40次写入、恢复文件并等15秒后仍约0.38核”的待核查线索。QA040以“环境开销已归因”关闭，产品修复0、新增产品缺陷0；不能称为已修复产品忙循环或泄漏。

该结论不意味着任何UIA连接都会造成高CPU，也未定位工具或Windows内部的具体缺陷；此前存在已连接却低占用的样本仍有效。原生连续滚动中的8秒输入断档尚未在断开客户端条件下复现或排除，QA008/034继续；长期资源、终端及UI组合验收仍保留。当前已知未关闭从10项变9项，七项目标继续，不推算完成百分比。
