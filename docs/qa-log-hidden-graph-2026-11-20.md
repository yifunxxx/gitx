# QA-047：树模式跳过隐藏的 Log 图线布局

日期：2026-11-20。来源：继续 QA-034/008 对 Log 和共享 VirtualList 的可见窗口、响应式数据与刷新路径进行只读审查后，使用真实组件确认隐藏计算。类别为已复现性能问题；不将函数时间等同原生输入到显示的延迟。

## 问题与复现

`LogView.vue` 的图线 watcher 原来只依赖提交和筛选字段，与 `logListMode` 无关。树模式没有 CommitGraphCell，却在首次挂载、提交刷新和前插时继续为整个已加载历史生成 lanes、edges、labels、输入快照；树行另外构建。宽历史的隐藏图线计算和保留对象都没有用于当前视图。

外部 probe 挂载真实 LogView、真实 Pinia logStore，截获真实 `layoutCommitGraphIncremental` 调用；仅替换与本项无关的后端/布局容器以及 VirtualList 的行呈现。数据是可合法拓扑排序的128条并行分支，每分支20个提交，再汇入共同根，共2561条。它不是用户仓库采样，也不包含浏览器布局或绘制。

| 树模式触发 | 修改前图线调用 / 生成边数 | 修改后图线调用 |
| --- | --- | --- |
| 首次挂载 | 1 / 311551 | 0 |
| 引用改名刷新 | 1 / 311551 | 0 |
| 前插新提交（2562条） | 1 / 311552 | 0 |

修改前上述三次图线函数用时分别32.306、31.568、39.909ms。这些是组件调用中的单次函数计时，不是滚轮延迟。修改后切回平铺时才调用一次，传入当前2562条历史；该次在并行验证负载下为73.390ms，不与前面的样本做快慢比值，也不声称平铺宽图已优化。外部probe中的 `graphCells=0` 受 VirtualList stub 影响，不用于证明平铺实际图形呈现；正式回归另使用渲染 slot 的列表 stub 检查图形组件及标签。

此外，使用同一图线函数及真实树行函数做1次预热、9次有界Node采样，修改前中位如下。图线算法本次未改；此表用于说明隐藏工作的规模。

已确认真实 store 的 commit 行不是深层响应式代理；图线结果、treeRows 也已使用 shallowRef。共享 VirtualList 的定高可见窗口仍按 start/end 有界取行，本轮没有恢复或重复修改已解决的50ms门控、绝对行号循环复用和路径树工作。

额外挂载真实 VirtualList 和 CommitGraphCell：2万条数据、400px默认视口、22px行高，连续12次每次一行的滚动共读取468次数组项（39×12），挂载图形组件保持39个，没有全历史扫描。1/40/128条lane分别保留39/1560/4992条SVG path，说明宽图水平裁切没有减少实际路径节点；这作为后续候选保留，本项没有修改图形绘制。测量环境为happy-dom，不包含真实布局/绘制，不将其tick时间作为原生延迟。

## 修改与验证

图线 watcher 增加模式依赖。进入树模式时取消未执行的图线rAF，清空图线布局及cursor，释放隐藏图线引用；树模式刷新仍正常更新树行。切回平铺时用当前历史和筛选选项重新调度布局，图形就绪前不复用旧历史的图线。平铺内连续加载仍保留既有增量布局和行对象复用。

新增正式 `LogGraphScheduling.test.ts` 共6项。修改前5项失败、1项平铺追加对照通过；修改后全部通过：

- 树模式挂载和提交/筛选刷新不调用图线布局。
- 从树切回平铺使用最新历史、引用标签和筛选选项。
- 同帧切到树模式会取消尚未执行的图线任务。
- 隐藏期间清空旧图，返回平铺前不呈现旧图形。
- 平铺追加合并待执行任务，并复用未改变的已有行图形。
