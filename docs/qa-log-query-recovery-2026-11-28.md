## 现象

LogView 在 `log.error` 时用完整 ErrorState 替换顶部筛选栏和历史内容。首次读取失败或错误筛选后，用户无法在原处修改条件、清除筛选或重试。历史查询也没有独立任务条目，慢查询时只能看到空列表，容易把“仍在读取”误认为“没有匹配”。

## 修改

- 错误改为显示在 Log 内容区域内，筛选输入、Apply、Clear、Go to 和分支面板保持可用。
- 错误区提供 Retry；重试重新使用当前草稿条件，并将焦点放回提交说明筛选框，方便继续改写输入。
- 独立前台查询进入任务队列，历史查询标题为“正在加载提交历史…”/“Loading commit history…”，向旧记录翻页使用已有加载更多标题，查询完成或失败都会收尾。项目打开控制器明确以 `taskOwned` 复用它的首次读取总任务；打开期间的后续用户查询仍单独登记。后台刷新保持静默，避免把轮询显示成用户操作。
- 加载中显示明确状态和 `aria-busy`；只有后端返回真正空页且加载结束后才显示无匹配空状态。
- 原有导航代次、筛选代次、详情请求和仓库归属保护保持不变；旧请求失败不能覆盖新仓库或新筛选结果。
- 中英文教程补充筛选失败恢复、任务队列和空结果区分。

没有修改 Git 查询协议或后端历史语义，没有加入重试循环，也没有把后台刷新强行放入队列。
