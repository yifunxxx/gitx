# QA163：终端文字、选区与块光标对比度

日期：2026-11-28。开始前读取统一台账，fetch并整合master/交付分支成功；基线`1472257a0b59d39eab42a49c4a89b2ba19358cf6`包含master`50a4802`。全程主线程。

## 问题与修复

QA007当前Windows原生续验观察到PowerShell黄色/浅灰文字偏淡，双击与拖选未能看清选区。进一步以真实TerminalView、xterm和产品CSS进行受控对照，确认浅色选区与背景实际为同色；本次没有把此前单纯未取得选区的工具结果直接认定为选择事件丢失。

根因及修改：

1. 产品将CSS token拼成空格分隔的`rgb(37 99 235 / 0.38)`。当前xterm 6解析器的直接路径仅接受逗号RGB/RGBA，canvas回退又拒绝透明度，选择色因而回退默认值。浅色的默认半透明白叠在白色背景上，选区不可见。现转换成逗号RGB/RGBA，保留原token颜色和透明度。
2. 原配置仅设置默认前景，不校正Shell输出的ANSI/256色/RGB颜色。在浅色背景下黄色、灰白字可接近背景。现启用xterm的`minimumContrastRatio: 4.5`，沿用其缓存和渲染实现，无额外逐字符JavaScript处理。
3. 补齐选择前景与块光标内字形色。原浅色黑色块光标中的默认黑字也缺少对比；现在光标使用前景、内部字形使用背景。

## 实际验证

真实组件/xterm浏览器对照在同一会话依次切换默认浅/深色、玻璃深/浅色，再回到默认浅色；新旧共10场，pageerror为0。每场渲染16种ANSI前景、256色、亮/暗RGB、自定义RGB背景、dim、inverse和块光标；通过产品右键菜单全选、工具栏复制，完整中文/Ω与颜色去除后的正文保持。光标测量只在测试页暂停CSS闪烁以采样实体色，不改变产品动画配置。

## 仍需核查的边界

DIM指令有意减弱文字，上游仅使用一半阈值且有透明度混合；默认前景的inverse路径在当前xterm中使用原foreground计算对比，然后渲染成背景色，浅色样本仍为2.507。两者已保留实际测量，不声称全部SGR序列符合文字对比标准；QA163对原生普通文字/选区/光标的修复与剩余inverse边界分开记录，后续需评估兼容性后再调整。

交付审阅另确认`ColorContrastCache`/`TwoKeyMap`按背景/前景配对保留结果，无显式容量限额；主题或选项变化时清空。本次启用对比校正后，长期输出持续变化的RGB是否造成显著存活增长尚未测量，归入QA163资源待核查，不能把普通20类颜色对照或关闭后释放扩展为长时运行无增长。下一步使用有界真实xterm负载测配对数量、GC后存活和渲染耗时，再决定是否需要限制缓存；没有据静态代码直接判定内存泄漏。
