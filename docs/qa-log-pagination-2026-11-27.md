# QA134：Log延迟分页的视口和上下文归属

日期：2026-11-27。每项开始先读台账并同步远端；本项基线 `fde2c2e3f1120fb66205f9d1af0b72976ca5ee38` 包含master `50a4802dd23f61055668e165f6fe7c0b93b17680`，版本0.1.56。全程主线程。

## 问题与修改

Log在距离底部不足80px时安排180ms延迟分页，用于避免滚动期间立即执行Git读取和图线布局。旧定时器只在重复安排或卸载时取消；用户随后滚离底部、切仓/同路径重开、修改筛选或切换显示模式，原回调仍可能调用当前store的loadMore。它也不复核视口尺寸和位置，列表增长或滚动事件尚未递送时同样会多读一页。

真实LogView、VirtualList及Pinia store的受控回归确认上述过期触发实际到达logQuery，故登记为已复现缺陷。这会增加不需要的Git读取和图线计算；没有测得该项CPU/帧时间改善，不将其归因为QA008/034原8秒输入断档。

修复只涉及LogView的分页调度：

- 滚离底部立即取消待执行定时器；执行前重新检查当前列表实例、视口高度、底部距离及鼠标按住状态。
- 通过已有仓库动作身份处理切仓、同路径重开和同tick往返；筛选、列表模式和提交窗口变更同步取消定时器。
- 提交窗口仅观察数组身份，不深遍历全部提交；小型筛选对象保留原地修改检测。
- 保留180ms合并、鼠标释放后重新安排、分页重叠校验和store原有防重/错误处理。
