# QA-096 部分提交事务保护

日期：2026-11-26。来源：继续QA-089/QA-095按块Changelist时核查现有`commit_create_ex(partial)`调用链。该接口已有真实Git回归，但现有产品界面尚未接入按块Changelist；本次修复其后端基础，不把它等同于完整块级列表功能。

## 基线和复现

开始前fetch及两分支快进检查成功，HEAD/交付分支`8765d71b500f0683918f5256ab749f2965a8ff32`，包含master`5241dd5d64683d03c6e3f5e901ea7293d2c199b3`，工作区干净。全部工作在`checkout-target-safety`工作树，由主线程完成。

隔离真实Git初始5项全部失败：

- 已有`index.lock`时仍创建提交，后续reset失败被忽略。
- 同文件另一处已暂存修改在成功提交后被reset取消暂存。
- 非UTF-8工作文件被有损解码，替换字符进入提交。
- 准备阶段过滤器失败后遗留固定`partial-index`。
- 同时传入有效和无效行号时忽略无效行号，仍生成提交。

以上为受控后端复现，不声称用户已经在产品界面触发数据损坏，也不归因于历史滚动问题。

## 修改

- 部分提交先持有真实索引锁，消息、提交索引、结果索引和原始索引快照置于唯一临时目录；正常成功或提交前失败均清理。全部Git子进程接入共享runner的取消、超时和进程树收尾。
- 从固定HEAD对象构造所选内容，仅提交有效修改行。使用严格UTF-8/普通文件检查；过滤器、编码转换、冲突、被暂存删除等无法可靠按行处理的情况明确拒绝；Git正常EOL清理仍支持。
- 结果索引从原索引复制。将所选内容与同文件原有暂存内容作三方合并，保留不冲突的未选暂存；重叠冲突在创建提交前拒绝。保留工作文件原字节与其他文件的暂存状态。
- 提交前再次检查工作文件原字节、HEAD/当前分支和真实索引。空、重复和同时混合整文件/部分选择不再退回全索引提交或静默忽略。
- Git报告成功后检查实际提交树与准备树；钩子改树、外部绕锁改索引、发布失败时保留恢复材料并返回成功附带明确警告。Git失败/取消但HEAD已前进也保留材料，提示先检查实际提交；若HEAD无法核对，明确报告结果未确定，不能当作成功。提交后的恢复使用独立取消令牌。
