# QA-123 选中文件提交安全复核

日期：2026-11-27。来源：用户要求复核其“提交部分文件可能丢失其他未提交修改”的修复方案。基线为已同步的 `origin/master` `8595638`，包含 QA-121 功能提交 `2a70101`；本轮交付分支为 `codex/search-polish-commit-review`。

## 对原方案的判断

以私有提交索引构造本次提交、以私有结果索引保留未选文件的暂存状态，方向正确。原有 8 项 `path_commit_safety` 回归全部通过，包含拒绝钩子时未选文件工作区字节、原索引和 HEAD 保持的对照。

但原实现重复了部分事务逻辑，遗漏了既有按块提交中的状态检查和提交后恢复保护；分别向两个索引执行 `git add` 还可能得到不同内容。本轮没有证明用户原始工作区修改丢失的具体触发链，也没有证明 `git commit --only` 本身就是原因。私有索引不能限制任意 hook/filter 自行改写工作区，不能承诺任意钩子环境下文件都不会变化。

## 已复现的问题

全部使用隔离临时仓库和真实 Windows Git，不操作用户项目数据。

- **进行中合并被部分提交提前完成**：`MERGE_HEAD` 存在时选择一个文件，生成缺少其他合并内容的合并提交，并结束合并状态。
- **钩子改树后发布旧索引**：pre-commit 额外暂存文件后，提交树已经变化，原实现仍发布事先准备的结果索引，且不提示恢复。
- **覆盖绕锁写入的真实索引**：post-commit 改写真实索引后，原实现未复核便覆盖该内容。
- **提交后取消误报失败**：post-commit 阶段 HEAD 已前进，取消仍返回普通失败并清除恢复材料，容易诱导重复提交。
- **两次 add 的结果不同**：非幂等 clean filter 会产生不同对象；原结果索引上的 `assume-unchanged` 也可能保留旧对象。两者均可造成提交成功后 HEAD 与结果索引不一致。
- **子模块提交回退**：读取子模块目录时调用普通文件读取，Windows 返回 os error 5，无法提交正常的 gitlink 更新。

新增事务回归在旧实现中 4 项失败，用户原拒绝钩子对照通过。首轮边界回归 4 项失败、1 项安全拒绝对照通过；其中 WSL 项只确认缺少早期门禁，使用已取消令牌避免启动 WSL，不是 WSL 数据损坏实证。

## 修复

- 整文件选择改为调用已有 `commit_selections` 事务，删除独立 `commit_paths` 实现，共用索引锁、进行中操作门禁、HEAD/分支身份检查、原索引复核和提交后的结果判定。
- 所有整文件选择合并为一次 `git add`；直接把准确的对象、模式和删除记录复制到结果索引，不再次运行过滤器。通过 NUL 分隔的标准输入传递选择，索引读取次数不随文件数增长。
- 对文件、链接、目录候选和子模块指针分别建立工作区快照，保留二进制及普通文件的原始字节语义。未选文件的暂存内容和工作区内容保持独立。
- 钩子改树、外部索引变化或 HEAD 已前进后的异常均保留恢复材料并明确反馈，避免将已创建提交报为可直接重试的失败。
- Windows 大小写路径按文件系统语义匹配；发现会混淆独立 Git 索引条目的大小写冲突时，在创建提交前安全拒绝。
- WSL 的选择文件/按块提交在操作私有索引前明确拒绝。可使用本机 Git，或提交整个暂存区；旧 QA-096 中“改用 whole-file”的建议不再适用于 WSL 的选中文件入口。
