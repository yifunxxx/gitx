# QA-038：远程管理的编辑与异步操作保护

日期：2026-11-19。来源：继续检查 UI 等待、取消和仓库/弹窗生命周期。范围限定为 `ManageRemotesDialog`，不修改后端远程命令。

## 已复现问题

1. 删除远程时先读取 A 仓库的预览，再等待确认；确认后重新读取当前 `ws.repoPath`。期间导航到 B 后，实际删除参数变为 `{ path: "B", name: "origin" }`，随后提示和刷新同样指向 B。
2. 编辑名称直接修改列表条目的 `r.name`，而输入框和 Save 的显示条件是 `editing === r.name`。输入新名称后条件立即失效，输入框和 Save 消失，无法保存重命名；原列表对象也已被草稿污染。
3. 初始读取没有等待/错误重试；添加、编辑和移除没有统一防重。卸载后晚到的预览仍可能打开确认，已替换弹窗中的旧写入完成还会提示成功和刷新当前页面。

先用实际 SFC 编译模板、Vue `createApp` 和 happy-dom 进行 DOM 点击/输入复现；后端和确认结果受控，无真实仓库写入。脚本和原始结果为 `E:/IDEAproject/gitx/test-results/remotes-component-probe-20261119.{mjs,json}`。

随后新增真实组件回归，保留实际 `useRepositoryAction`、对话框栈及响应式仓库身份；初始 **8 项全部失败**，没有把失败结果当作待测猜测。日志 `remotes-lifetime-before-20261119.log`。

## 修改

- 打开弹窗时固定仓库路径、仓库身份、导航代次和父弹窗 ID。导航变化关闭自己的弹窗与自己创建的确认；其他提示不受影响。迟到结果、已卸载或已移除的弹窗不能再提示、刷新或提交。
- 删除预览、确认及写入使用同一组固定参数；确认返回时再次检查当前仓库和父弹窗。取消确认后可正常重试。
- 编辑使用独立草稿，保留原远程名作为后端标识。改名后输入继续显示；Cancel 丢弃草稿；保存失败保留输入，成功后清理草稿。
- 统一读取、预览、确认、写入阶段，显示等待并禁止重复操作。初始读取失败提供 Retry；写入失败展示错误并允许重试。写入过程中阻止关闭/逃逸，普通读取可关闭；组合输入中的 Escape 不误关弹窗。
- 写入成功后分别刷新远程列表和分支。刷新失败明确说明操作已成功，Retry 只重新读取，不再次执行添加、编辑或删除；列表未能刷新时禁止使用旧列表继续写入。
- 补充弹窗语义、输入标签及按钮可访问名称，保持现有英语界面用词。

`branches.refresh()` 自身保留路径、导航与请求代次保护。后端 `remote_add` 的可选 fetch 当前丢弃 fetch 错误并返回添加成功，因此该分支不会导致前端误把已添加视为 action reject；本次没有修改或声称改善该后端行为。
