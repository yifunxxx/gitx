## 范围与来源

QA-036 上一轮已统一欢迎页及标题栏。本轮继续检查全局 `File.OpenFolder`、`Git.Init` 和当前目录 `Start.Use.Vcs` 入口：它们仍直接调用选择器或工作区 store，未共享等待状态；旧请求结束后还会触发成功提示、刷新和布局切换。来源为动作定义审查，现已自动复现。

影响：快捷键、菜单与欢迎页可交叉发起重复操作；切换目录后旧选择器返回的目录会再次导航，旧动作也会覆盖当前界面反馈。使用真实 action registry、真实 Pinia 工作区及布局 store，控制原生目录选择器与后端 Promise，先保留失败基线再修改。

## 修改前证据

新增 `vcsOpen.test.ts` 首轮稳定基线 10 项全部失败，无未处理错误。日志：`E:/IDEAproject/gitx/test-results/open-actions-before-20261119.log`。

- 初始化初始读取仍在进行时没有共享等待，读取串行开始。
- action 打开失败直接 reject，没有进入欢迎页可读错误及重试状态。
- 连续两次 `Start.Use.Vcs` 实际调用后端两次；导航后旧成功仍显示 “Git enabled” 并刷新。

## 修改

- 将共享逻辑拆为接受翻译函数的 `createWorkspaceOpen`；组件包装器仍使用 `useI18n()`，action 使用 `i18n.global.t`，无需在组件 setup 中执行。
- 三个 action 接入同一 Pinia 实例的共享 operation、等待目录、错误和导航身份。选择器、打开、初始化和初始读取期间跨入口防重；旧选择、成功、错误和 finally 均不能覆盖新操作。
- `isWorkspaceOpening()` 只读取已有 WeakMap 状态和工作区导航号。菜单 `enabled` 查询不创建控制器、额外 store 或监听器。
- 当前目录启用 Git 同样加入等待与防重，成功后显示本地化“仓库已创建”及目录，打开 Git 面板，并行启动 Changes、Log 和 Branches 读取；所有读取结束后才释放等待。空目录状态不会触发选择器或初始化。
- 继续保留原导航立刻释放过期等待、欢迎页卸载后读完、取消与失败重试及不同 Pinia 隔离。
