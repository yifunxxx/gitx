# QA-036 克隆完成后的打开与导航续查

日期：2026-11-19。基线：`3d5641f`（0.1.40）。

## 来源与范围

全局打开入口报告保留 `Git.Clone` 完成后的打开/首读待核查。本轮检查真实 action registry、Pinia 工作区、欢迎页按钮、DialogHost 与 CloneDialog；使用可控后端 Promise 复现交叉入口和过期导航，不执行真实远程克隆。

代码路径：CloneDialog 自身已有克隆防重、取消 job、鉴权重试和可读错误；`Git.Clone` 在对话框返回目录后直接打开、串行首读，没有共享打开等待，也未捕获发起时的导航身份。重复调用 action 会叠加多个克隆弹窗。以下自动回归已经复现这些问题。

克隆可能耗时，不因本轮修复锁住所有项目操作。导航后旧克隆完成应保留完成反馈，但不能强制跳转新目录；真实取消及目标目录安全仍沿用现有克隆实现。

## 修改前证据

新增 `m2Clone.test.ts` 使用真实注册动作、Pinia workspace/layout、WelcomeView、DialogHost 和 CloneDialog，控制克隆/打开/读取 Promise。基线 **6 项失败，1 项通过**，无未处理错误；日志：`E:/IDEAproject/gitx/test-results/clone-open-before-20261119.log`。

- 欢迎页重复点击及菜单动作能打开多个 CloneDialog。
- 克隆过程中允许打开其他项目，但克隆完成仍强制导航到旧克隆目录。
- 克隆完成后 `workspace.openFolder` 及首读没有共享等待，欢迎页和标题栏相关入口仍可重复打开。
- 克隆成功、打开目录失败时 action 直接 reject，欢迎页没有可读错误。
- 打开阶段被新导航取代后，旧结果仍刷新当前仓库并切换 Log 面板。
- 新目录选择器已经打开、尚未返回时，克隆完成会先打开旧克隆并打断新选择。
- 取消及关闭“完成后打开”基线通过，作为保留行为回归。

## 修改

- `Git.Clone` 为每个 Pinia 工作区记录一个克隆对话框占用，action 查询和执行都防重；`finally` 在取消、关闭及完成后释放。查询只读取状态，不分配控制器或监听器。
- 发起克隆时捕获导航号；其他导航（包括同一路径重开）发生后，成功克隆保留完成提示，但不再自动打开。
- 克隆阶段不持有共享工作区打开状态，原有其他项目入口继续可用。
- 新增共享控制器 `openCloned(path)`，在克隆完成后的打开阶段展示加载路径、跨入口防重、并行启动 Changes/Log/Branches 首读，并等待全部结束。已有导航/错误/finally 身份保护继续适用。
- 如果克隆完成时新选择器占用共享打开状态，则直接放弃自动跳转，不排队延迟覆盖用户选择。CloneDialog 已显示完成提示，打开阶段不重复显示成功 toast。
- CloneDialog、欢迎页和真实后端克隆/鉴权/取消/目录处理未修改。
