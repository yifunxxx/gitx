# QA-095 按块Changelist：核查与实施约束

日期：2026-11-26。承接QA-089最后一个功能子项，不重复计数。开始前fetch/快进检查成功，基线`8765d71`包含远端master`5241dd5`；主线程独立执行。

## 已确认的现状

- `HunkAnchor`、`PathAssignment.hunkRanges`和设置`allowPerHunkChangelists`存在，但实际分配只调用`move_paths`。
- `changesStore.assignmentByPath`只保存一个listId；文件只能显示在一个分组。`checkedPaths`只有路径，无法表达同文件只勾选某个列表的修改。
- `ChangesTree`的文件/文件夹/列表复选框、`CommitToolWindow`菜单和`CommitFilesDialog`都需保留列表归属，不能只在Diff增加分配菜单。
- `commitStore`当前传整文件paths；仅改变分组显示仍会把同文件另一列表的内容一起提交。
- metadata删除列表时清空hunkRanges；整文件移动只修改第一条同路径记录。支持多条块归属之前必须明确整文件覆盖与列表合并语义。
- 部分提交后端基础存在独立已复现缺陷，先由[QA-096](qa-partial-commit-transaction-2026-11-26.md)修复。此基础修复不关闭本项。

## 完整功能的验收约束

1. Changelist模式HEAD→Worktree差异提供逐块分配入口及可读的列表归属；设置关闭时停止新的块分配，已有部分归属不能被一次提交静默扩大成整文件。双栏/统一、折叠/展开和纯删除均需覆盖，Diff仍只读。
2. 内容锚点由后端根据实际预览生成。行号偏移可以重定位；相同内容多处出现或变更合并/拆开导致不能唯一识别时，需要可见提示和保守的提交校验，不能仅按旧块序号操作。
3. 同文件可同时出现在多个列表，带部分归属说明。勾选状态必须按列表与路径区分，文件夹和列表聚合保持一致，现有紧凑树/多选提交窗口继续共用。
4. 整文件移动明确覆盖该文件全部块归属；删除列表仅迁移其拥有的块，不能清除其他列表在同文件上的归属。重名、活动列表、仓库切换和刷新迟到结果均有回归。
5. 提交选中列表/文件时，后端重新核对归属和预览，再从HEAD构造精确内容。混合整文件与部分文件、纯删除、首次提交、已有暂存、钩子失败/取消都必须验证，未选工作内容保持。
6. 文件外部编辑、行号偏移、块消失、多个相同块、列表删除后的旧窗口不能造成误归属或扩大提交范围。默认/活动列表对新块的规则需在界面与文档中一致说明。
7. 重计算只限存在部分归属的文件，避免每次状态刷新为所有文件生成Diff；相同归属数据不应触发大树重复重建。
8. 等待、防重、任务队列、写成功但读取失败后的重试、源仓库/标签/导航归属继续沿用QA-094模式。使用共享提交成功附带警告契约，避免恢复失败被当作可重复提交。
