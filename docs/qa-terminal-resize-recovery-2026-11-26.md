# QA117 终端尺寸请求失败后的恢复

日期：2026-11-26。基线 `b89cec50fa46025af078b04a4a851c7f4f44c25a`，包含 master `fdc51568d102e731aeaafb3fa62b9f7a28dff12c`，版本 0.1.49。开始前及提交准备前 fetch、master/交付分支快进检查成功，无远端新提交。全程主线程。

## 发现与修复

终端连接会合并连续尺寸变化，但异常捕获位于整个发送循环外。在途 90×30 请求失败时，已排队的最新 120×40 尺寸没有继续发送；需要再发生一次面板尺寸变化才能重新启动队列。终端显示与 Shell 列数可能由此不一致，影响换行、光标及全屏程序布局。

此问题由代码审阅和受控失败回归确认，未取得自然原生 IPC 失败的复现。不是对整体滚动卡顿的根因结论。

把异常处理限定到每次尺寸请求：失败后报告既有错误，并继续发送当时最新的排队尺寸。失败的尺寸不会自行重试；所有请求串行执行，关闭或退出后不继续发送，也不显示晚到的尺寸错误。没有增加计时器、后台重试或新的用户操作。
