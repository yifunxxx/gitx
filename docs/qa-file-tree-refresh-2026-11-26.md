File树的同步选择修剪监听依赖整个行数组。原实现中，刷新每个目录时的loading变化和相同entries替换都使全部行重新构造，并发布内容未变的selectedPaths数组。紧凑目录额外依赖loaded标志；刷新先把所有loaded置为false，暂时拆开压缩链。按`src/one`组合名称筛选并选中该目录后，未变化刷新也会使筛选结果暂时为空、选择被同步清除。

计时为同机同单文件执行范围、真实Vue开发模式/store加模拟IPC，包含IPC结果复制与选择监听，没有真实磁盘读取、原生绘制或滚轮输入。不能把数值当作生产帧延迟或全部卡顿的改善比例；测试没有固定毫秒阈值。证据目录`E:/IDEAproject/gitx/test-results/qa104-file-tree-refresh-20261126`保存before.log/after.log/after-final.log。

## 修改

- 用stale单独表示需要重读，成功目录快照在等待和失败期间保持。紧凑目录根据上一次实际结构显示，避免未变刷新先拆开再合并。
- 按顺序比较path/name/kind，实际变化才发布新entries。IPC数组作为只读快照保留，避免深层响应代理；不增加历次结果缓存。
- 行的loading/error由消费者读取响应状态，不再让短暂等待触发全树重建；紧凑链把隐藏父目录的加载和失败也呈现在可见目录上。普通文件不持有目录状态闭包。
- 紧凑目录点击重试时，先重读过期的隐藏父目录；等待后重新检查当前导航和目标，避免链已替换或项目已切换时继续读取旧子目录。
- 只有隐藏或消失的选择被修剪时才更新selectedPaths；筛选、折叠、删除、目录变文件仍清理无效批量目标。
- 保留QA090的目录身份/世代、旧请求隔离、同路径重建，以及父先子后的刷新和合并失效语义。
