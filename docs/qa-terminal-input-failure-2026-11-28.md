# QA144 终端写入失败后的输入隔离

日期：2026-11-28。开始前读取台账、fetch和master/交付分支检查成功，干净基线`d544aed1b5cb5b00e29bed904325f31da8026610`包含master`50a4802dd23f61055668e165f6fe7c0b93b17680`。全程主线程。

## 发现及修复

TerminalConnection将输入串行分片发送，旧实现在某次写入失败后仅报告错误，后续排队输入仍继续发送。后端的write_all/flush错误不能保证此前没有写入前缀，因此后续回车可能执行残缺输入。来源为终端传输和资源释放审阅，再以受控IPC失败确认；未声称有自然原生命令误执行。

输入发送失败现在立即把连接标为结束，停止后续分片、排队文字和回车，取消排队尺寸，解除正在等待的输出解析回调并请求关闭PTY。旧读取/尺寸/写入结果不会再发布到已结束连接，关闭标签与故障清理共用同一次关闭Promise。正常终端的尺寸失败仍按既有规则处理，不因它关闭会话；输入队列容量校验失败尚未发送内容，也不结束健康连接。

界面保留已有输出和明确的中英文错误，禁用会话输入与粘贴，允许新建终端恢复。不会重发失败输入，也不能撤销此前已到达Shell的字节或已经执行的操作。中英文教程补充检查原操作结果、建立新终端继续的恢复路径；没有新增快捷键。
