# QA-077 分支操作的仓库归属保护

日期：2026-11-23。主线程独立完成。开始前成功fetch，基线`2f80c414a7d06105d16d0ce27213058da9821195`包含远端master`42df3f730be8ddd157a6aaca8d9a2b908638c950`及交付分支最新提交，工作区干净。

## 问题与复现

分支面板和顶部弹出列表在等待新建、重命名或删除确认后，直接调用读取当前workspace的store方法。若等待期间开始新导航、切换仓库或组件卸载，旧确认仍能提交；从A切到B时，真实store向backend传入`path: B`，重命名还传入`gitDir: B/.git`。旧右键菜单也没有在导航开始时失效。

已发出的操作自身参数固定，但完成后store会刷新新仓库；组件还会继续刷新Changes、Log、Refs并显示旧成功/失败提示。刷新链中途导航时也没有中止后续读取。

新增真实BranchesPane/BranchesPopup与真实branchesStore联合回归，只有backend、弹窗Promise及无关store受控。旧实现37项中**31失败、6正常流程通过**；日志`E:/IDEAproject/gitx/test-results/qa077-before-20261123.log`保留实际错误参数。这是可重复的条件性逻辑缺陷，不声称用户已经误删分支；测试没有执行真实Git修改。

## 修改

- 两个分支入口复用`useRepositoryAction`，捕获仓库、导航代次及组件生命周期。在弹窗等待、backend返回和每段刷新之间核验归属；过期确认不执行，迟到结果不提示、不刷新新界面。
- 导航开始时关闭旧菜单，弹出列表同步关闭；面板本地选择状态清理。同路径重新打开也使旧操作失效。
- 远程删除在动态加载backend后再次核验，用捕获路径调用；合并、变基及拉取后的刷新链也受归属保护，旧操作不会关闭新打开的分支弹窗。
- store的新建、改名、删除、恢复和更新分支捕获写入参数及导航身份，仅在身份仍匹配时执行后续引用刷新。已发出的Git操作不因界面失效而自动回滚，原返回值和错误保持。

CreateTagDialog本身的写入生命周期与CompareBranchesDialog的Swap请求顺序是另外两项静态候选，登记QA-078/079继续核查。本次只保护顶部“新建标签”返回后的列表刷新，不宣称标签创建内部已修复。
