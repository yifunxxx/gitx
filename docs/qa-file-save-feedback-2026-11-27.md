## 问题与修改

文件保存先写入磁盘，再读取HEAD差异来刷新行标记。旧实现把可选差异读取也包含在saving期间：磁盘写入已经成功，保存Promise、Commit刷新及下一次保存仍受慢Git读取阻塞。后续保存请求会直接返回false，最新草稿保持但没有写入磁盘。受控回归确认此行为，不把它等同于滚动卡顿的根因或磁盘写入丢失。

另外，保存后仅核对编辑器正文，没有检查diff.rightText。外部程序在保存后改动磁盘、后端省略正文或Git读取失败时，可能显示另一份快照或之前正文的行标记；保存后超出辅助差异阈值也会保留旧标记。

- 保存状态仅覆盖实际写入；成功即更新baseline/dirty并刷新Commit。实际写入期间仍防止并发保存，写入失败仍保留草稿并提示错误。
- 行标记在后台读取，每个标签最多一个在途请求和一个最新待办。多次保存不会为每个中间版本并发运行Git差异；失败后继续处理最新待办。
- 只接受当前标签、路径、仓库导航和已保存正文均匹配的结果，并核对diff.rightText。成功写入后的过期标记清空；保存期间新产生的草稿及其映射标记不被强行重置。
- 新写入、关闭、移动（包括移走又移回）、仓库导航和store销毁会让旧请求失效、丢弃排队读取。读取本身继续使用后端原有超时，没有新增取消IPC或更改Git超时。
- 不重建编辑器，保持选区与撤销记录；完整文件读取/保存能力及既有大正文辅助差异阈值保持。
