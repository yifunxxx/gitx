## 问题与修改

File的创建文件/目录、重命名、复制、移动和回收操作只设置busy来禁用部分入口，fsMutate没有原生JobManager任务，也未通过前端活动观察器登记。慢复制时任务队列会显示空闲，File面板也缺少执行中的文字提示。普通非Git文件保存使用的fsWriteFile同样没有活动登记；Git文件保存的fileWriteWorktree已有登记，不重复修改。

旧实现的新增/既有组合29项中9项失败、20通过。六种文件操作和普通保存的延迟IPC检查均观察到空任务列表，另两项导航检查缺少面板状态契约；并非认定用户现场已复现自然慢磁盘。修复在确认和已有保护检查通过后创建一个带工作区路径的文件任务，覆盖实际执行、树刷新及新文件打开，成功、部分失败、异常和导航失效均通过finally结束。确认取消和前置拒绝不产生运行任务，不提供后端尚不支持的取消或虚构百分比。

File面板增加当前操作名称与旋转指示。切换工作区/导航后旧操作的面板提示消失，队列继续标明旧工作区直到实际结束；旧结果不能更新新树或弹出过期成功/错误。store销毁后不再发布旧结果，结束回调绑定原jobs实例，不能移除重建store中的同名任务。fsWriteFile通过共享活动观察器记录保存及folderPath，不将正文加入任务描述。fsMutate仍由store拥有完整生命周期，后台目录/文件读取不产生重复任务。
